# NewsKG Schema 流水线：怎么跑、怎么断点续跑

这份文档记录四步 Schema 化的**实际实现**与**运行约束**，配合 `PLAN_FOUR_STEPS.md`（当时的计划）一起看。
计划里对未来数据量的估算有偏差，以本文的实测为准。

## 0. 环境与入口

```powershell
$env:PYTHONPATH="src;.kgvenv"
.\.venv\Scripts\python.exe -m newskg.schema.cli --step <step> [参数]
```

数据库：`out/kg.sqlite3`（单文件，先备份过 `out/kg.sqlite3.bak-before-schema`）。

步骤与顺序：

| 步骤 | 命令 | 要不要模型 | 作用 |
|---|---|---|---|
| 关系种子 | `--step rel`（先跑 `seed_dict`） | 否 | 字典直配谓词 |
| 关系归一 | `--step rel --batch 50` | 是 | 2210 谓词 → 25 族 |
| 实体预标 | `--step type`（rule 段） | 否 | 正则/后缀规则 |
| 实体类型 | `--step type --batch 50 --min-degree 3` | 是 | LLM 判类型 |
| 类型传播 | `--step propagate` | 否 | 按谓词规则从邻居推类型 |
| 合并候选 | `--step merge --batch 50` | 是 | 四层候选 + LLM 判定 |
| 并查集聚类 | `--step resolve` | 否 | 别名 → 规范名 |
| 实体消歧 | `--step sense --limit N` | 是 | 每实体的边分配义项 |
| 校验 | `--step validate` | 否 | 谓词覆盖 / 其他族占比 |
| 出报告 | `--step report` | 否 | `out/labels/*` |

`--timeout` 控制单次调用的**读**超时（默认 600 秒）。批量小的时候要调小，
否则一次挂死会占掉半小时（3 次重试 × 超时）。

## 1. 关系归一（谓词 → 关系族）

三层：字典直配 → LLM 按位置作答 → 人工复核。

- LLM 的提示词**只给谓词和两个端点的前 12 字**，不给标题、不给完整三元组。
  早期给完整上下文的版本，一批 200 条要 16.6 分钟，而且模型会跑题。
- 输出约定是**按编号顺序的族名数组**（`["任职","其他",…]`），比让它输出
  `[{"i":1,"family":"任职"}]` 省一半 token，也少一类解析错误。
- 泛动词（`完成/通过/启动/进入/来自/打造/布局/获取` 等 19 个）被**人工改判进「其他」**，
  `decided_by='human'`。理由：它们的语义取决于上下文，硬塞进某个族就是错标。
- 不删任何边。`其他` 是兜底，保留原谓词。

`--step validate` 会给出：`predicates_total / mapped / missing / other_edges / other_ratio / families_used`。
验收线是 `other_ratio < 0.15`。

## 2. 实体类型（12 类 + 未标注）

`ETYPES` 是封闭集：机构组织、公司企业、产品型号、人物、地点行政、地点设施、
活动事件、技术概念、作品内容、泛称角色、数值度量、其他。不在其中的一律 `未标注`。

三层来源，`decided_by` 区分，报告里分开统计：

1. `rule`：后缀/正则（`有限公司`→公司企业、`大学`→机构组织、`省/市/县`→地点行政…）。
2. `llm`：批量判，一批 50~100 个实体，每个给 1~2 条边当证据。
3. `propagate`：**不花模型**。用谓词 + 另一端类型投票，例如
   - `X --任职于--> Y` 且 Y 是机构 → X 是人物
   - `X --举办于--> Y` → X 是活动事件、Y 是地点行政
   - `X --收购--> Y` → Y 是公司企业
   要求票数集中度 ≥ 60%，置信度记 0.6，明显低于 LLM 的。

**为什么「未标注」是合法输出**：只出现一次的实体，一条边推不出类型，硬标就是猜。
报告里会写清楚有多少个 `未标注`，而不是拿 `其他` 填充（那会把「不确定」和
「确实是杂项」混成一个数）。

## 3. 实体合并（别名 → 规范名）

四层候选，逐层收紧：

1. `seed_alias`：图里的别名边（`简称/全称/别名/又称/又名/缩写`）。
   **方向必须按谓词定**：`X --简称--> Y` 里 X 是规范名；`X --全称--> Y` 里 Y 是规范名。
   早期按度数选规范名，导致「进博会」把「第九届中国国际进口博览会」吃掉。
2. `norm_key`：去空白/括号/`集团有限公司` 后同 key。
   **不要剥「第X届」**——剥了会把第四届和第九届进博会并成一个。
3. 子串包含（长度差 ≤ 2，且类型相同）。
4. 编辑距离（`difflib` ≥ 0.80，首字相同，长度差 ≤ 2）。

**类型相等是硬约束**：`中国` 与 `中国移动` 类型不同，永远不会进候选。
这条比任何相似度阈值都管用。

LLM 只回答 `yes/no/unsure`，规范名由 `(度数, 长度)` 决定，不让模型选——
模型选规范名时会偏爱短名，把全称丢掉。

`resolve` 用并查集做传递闭包，重选规范名（度数最高者），**保留每对原来的 method**，
只有传递推导出来的边才标 `closure`。

## 4. 实体消歧（一个名字 → 多个义项）

判定单位是**每条边（mention）**，不是实体字符串。

- 候选：度数 ≥ 6、名字 2~8 字、邻居类型多样性高的实体。
  早期用「组织侧/物体侧是否均衡」排序，结果每个候选都恰好 0.5，等于没排序。
- 每个实体一次调用，给 10 条边（按另一端类型轮转抽样，保证稀有类型不被挤掉——
  苹果那 94 条边如果按库顺序取前 10 条，全是公司，`机器人手指 --抓握--> 苹果` 永远进不来）
  + 前两条边各配一段原文片段。
- 输出 `{"senses":[{"id","label"}], "assign":[{"i","sense"}]}`。
  **模型经常把整份结果包在单元素数组里**，解析时要解包。

## 5. 运行约束（实测，重要）

- **一次只跑一个流**。`ask_json` 从不并发。
- **大请求会挂死**：一批 300 条关系归一挂了 20 分钟无响应；50 条稳定在 70~170 秒。
  这不是超时设小了，是端点不返回。
- 吞吐随时间段波动很大：同一批量在下午是 86 秒，晚上会变成 6 分钟。
  长尾任务（deg=1 的几千个实体）不要指望半小时跑完。
- `llm_cache` 按提示词哈希缓存，重跑不重复付费；`schema_runs` 记录每批成败。
  所以任何一步都可以 Ctrl-C 之后原命令重跑。

## 6. 已知遗留

- `merge_report.csv` 里 2026-11-22 那次运行的 350 对判定，`method` 曾被旧版
  `resolve()` 覆盖成 `closure`，原因无法从库里恢复（除非重判）。代码已修。
- LLM 合并判定只覆盖了候选池的一部分（约 460 对未判）。未判的**不合并**，
  属于漏并而不是错并。
- deg=1 的长尾实体按吞吐能力逐步补齐，未补的保持 `未标注`。
