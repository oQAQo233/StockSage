## 5. 为什么只做到 7 个源（实测证据）

目标要求 10 个「能按日期回溯」的源。这一轮把能想到的路都验了一遍，命中的只有两类，
其余全部卡在「列表页不能服务端翻页」或「列表里没有日期」。

### 5.1 失败的一类：门户频道的 JS 翻页

| 候选 | 尝试方式 | 实测结果 |
|---|---|---|
| 澎湃新闻 | `channel_25951?page=N` | 每一页返回**字节完全相同**的 69141 B |
| IT之家 | `list/{p}.html` | 每页都是同样的 28199 B，且只覆盖 11-17~11-19 |
| 新浪科技 | 滚动页 `?page=N` | 同样是固定一页 22030 B，且列表里没有日期 |
| 人民网 | `1057/index*p*.html` | 页面里没有日期 |
| 钛媒体 / 雷锋网 / 科技日报 sitemap | 站点地图 | 只保留今天和昨天（34 / 3000 / 200 条，最新都是 11-19） |
| 界面新闻 | `lists/N.html` | 97 条链接但**列表里 0 个日期** |
| 新华网 | `/tech/index.htm`、`/tech/2.htm` | 前者无日期，后者 403 |
| 光明网 / 环球网 / 中国日报 / 央视网 | 频道页 | 404、0 链接、无日期、翻页页 404 |

### 5.2 命中的第一类：报纸电子版（按日出版，URL 写死日期）

| 源 | URL 模板 | 8 天篇数 |
|---|---|---|
| 证券日报 | `epaper.zqrb.cn/html/YYYY-MM/DD/node_N.htm` | 4 |
| 经济日报 | `paper.ce.cn/pc/layout/YYYYMM/DD/node_NN.html` | 9 |
| 上海证券报 | `paper.cnstock.com/html/YYYY-MM/DD/node_N.htm` | 23 |

其余电子报（人民日报、光明日报、中国证券报、中国青年报、经济参考报、工人日报、证券时报、
每日经济新闻、21 世纪经济报道、新京报、南方都市报、南方日报、广州日报、深圳特区报、
羊城晚报、新快报、科技日报）全部实测不通：`paperindex.htm` 是 400~600 字节的 JS 空壳，
或日期路径直接 404。**科技日报最可惜**：`epaper.stdaily.com` 整站是 SPA，服务端取不到版面 HTML。

### 5.3 命中的第二类：部委网站的老式服务端分页

这是本轮最后找到的一类，命中 2 个（实现见 `src/newskg/sources/govlist.py`）：

| 源 | 频道 | 分页形态 | 8 天篇数 |
|---|---|---|---|
| 科技部 | `most.gov.cn/kjbgz/`（科技部工作） | `index.html` / `index_1.html` … | 2 |
| 国家发改委 | `ndrc.gov.cn/xwdt/xwfb/`（新闻发布） | 同上 | 7 |

判定标准是三条同时成立：列表页能解析出 ≥8 条带日期的条目、第 2 页内容与第 1 页不同
（证明是服务端渲染）、日期跨度能覆盖 11 月初。

写适配器时踩到两个坑，都记进了代码注释：

1. **`<li[^>]*>` 会把 `<link href=...>` 当成列表项**，必须写成 `<li\b`；
2. **整页里混着侧栏/页脚的旧链接**，一起解析会让「本页覆盖哪几天」失真、翻页判断失效，
   所以只解析主列表容器（`<ul class="info_list2">` / `<ul class="u-list">`）。

同样标准下又探了 8 个机构站，全部不通过：中科院、基金委、中国信通院、国家数据局、
北京科委、上海科委的列表页是 200~2500 字节的 JS 空壳；中国科协的列表**没有日期**；
中国工程院那个 URL 是文章页而不是列表。这一类到此为止。

> 这 2 个源每天只有 0~4 篇（部委发布频率本来就低），所以它们对图规模的贡献很小，
> 但它们的价值在内容——科技政策、重大专项、区域规划，实体关系比综合新闻更集中。

## 6. 工程要点（本轮真正解决的两个难题）

### 6.1 「抽取一跑就挂」的根因是模型，不是并发

用 `faulthandler` 抓取调用栈，卡点稳定停在 `ssl.py read → urllib3.getresponse → requests.post`：
请求发出去、服务端收下却一直不回，`requests` 的 90 秒超时也没能按时触发。

根因是 `DirectExtractor` 默认模型是 **`qwen3.6-flash`**，它在这种长生成请求上会「收下不回」。
换成 **`qwen3.7-plus`** 后，同样大小的请求 20~35 秒稳定返回，连续 12 次零失败。

### 6.2 并发分片从「必卡死」变成「4 倍提速」

旧结论「多进程分片必卡死」是在 `qwen3.6-flash` 下得出的，换模型后不成立：

| 方式 | 实测吞吐 |
|---|---|
| 单进程 | 43.6 秒/篇 |
| **4 片并行（`--shard i/4`）** | **11.7~14 秒/篇，零失败** |

另外发现一个环境陷阱：**抽取进程必须由 PowerShell 的 `Start-Process` 启动**。
同样的命令放进后台任务、或由 Python 的 `subprocess.Popen` 拉起，都会卡在第一行不动；
而 `Start-Process -NoNewWindow` 起的子进程一切正常。

最终 3799 条三元组的抽取在约 100 分钟内跑完（平均 12~14 秒/篇，含中途定位模型问题的时间）。

```powershell
$env:PYTHONPATH="src"

$env:NEWSKG_TOPIC_MAX_SCORED="600"

    --days 15 --limit 10 --topic-mode keyword --topic-threshold 3

# 2) 抽取（4 片并行，需显式指定模型）
$env:NEWSKG_BACKEND="direct"; $env:NEWSKG_DIRECT_MODEL="qwen3.7-plus"
$py = ".\.venv\Scripts\python.exe"
for ($i=0; $i -lt 4; $i++) {
  Start-Process -FilePath $py -ArgumentList '-u','-m','newskg.cli','build','--backend','direct',
    '--limit','10','--shard',"$i/4" -NoNewWindow -Wait
}

# 3) 出图
.\.venv\Scripts\python.exe -m newskg.cli export --format all
.\.venv\Scripts\python.exe -m newskg.cli stats
```

## 8. 必须交代的口径与局限

1. **源 7/10 未达标**。这是本轮最大的缺口，原因是结构性限制（见第 5 节实测），不是漏做。
2. **11-11 的筛选口径与其余 7 天不同**：11-11 用关键词打分（阈值 3），其余 7 天用 LLM 打分。
3. **三个电子报源贡献很小（合计 36 篇）**：它们是财经报，科技题材本来就少；两个部委源合计 9 篇——低频但内容集中。
4. **抽取器混用**：41 篇走 KGGen（约 22 条/篇）、384 篇走 llm-direct（约 9 条/篇），
   图里不同来源的密度不均；若要统一，可对 KGGen 那批用直连再抽一遍取并集。
5. **实体归一仍有缺口**：同一事件的不同写法会分成多个节点，例如
   「2026年世界互联网大会乌镇峰会」分别连到「浙江乌镇」和「乌镇」。
6. **日期按 UTC 统计**：中文站是北京时间，凌晨稿件换成 UTC 会落到前一天，
   所以「入库数」与「按天统计数」可能差几篇。
