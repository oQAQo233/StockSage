# StockSage 项目计划书：新闻与股票多维度数据融合分析

## 1. 项目定位与研究问题

StockSage 面向本科数据融合课程，构建一个能收集新闻与股票数据、建立可追溯知识图谱、执行融合分析与预测实验的研究助手。核心交付不是展示一条预测曲线，而是说明**哪些来源的信息、在什么时点、通过什么方法，变成了哪些可检验的结论**。

建议正式项目首先聚焦 **A 股、日频、5—20 只股票、1—2 个行业、连续 6—24 个月**。具体规模取决于可合法获取的数据质量；预测结论需要足够多的独立测试日期。事件研究还要保留研究区间之前的估计窗口。此建议是范围约束，不是执行时间安排。

需要回答的研究问题：

1. 如何统一新闻、证券、上市公司、行业和交易日这些异构信息？
2. 如何把“新闻发布日期”转换成“预测时点真正可用的信息”？
3. 加入新闻情绪、事件类型、新闻数量或图谱关联后，是否比纯行情基线有增量？
4. 新闻与价格的共同变化如何展示？哪些只是相关，哪些还需因果识别？
5. 多个角色如何通过工具和共享证据协作，生成有出处的研究摘要？

**明确非目标**：高频交易、自动下单、保证收益、全市场实时覆盖、用 LLM 凭文本直接给出可靠股价。课程展示中的预测为统计实验。

## 2. 需要收集什么信息

### 2.1 证券与公司主数据

| 信息 | 关键字段 | 用途与注意点 |
|---|---|---|
| 证券标识 | 交易所、证券代码、证券类型、币种 | 代码需包含市场维度，避免跨交易所重名 |
| 公司主体 | 公司全称、简称、历史名称、统一主体 ID | 将新闻中的简称映射到公司；保留有效期 |
| 公司别名 | 常用简称、品牌、子公司、英文名 | 子公司与母公司关系需证据；不能简单字符串命中就认定 |
| 行业与板块 | 分类体系、行业代码、所属行业、生效区间 | 行业分类随时间变化，不使用当前分类反填历史 |
| 上市状态 | 上市日、退市日、ST 状态、停复牌记录 | 降低幸存者偏差，解释缺失行情与交易限制 |
| 公司行动 | 分红、拆并股、送转、配股、复权因子及可用时间 | 统一价格口径，避免把除权缺口当成新闻冲击 |

### 2.2 行情与市场环境

必需：证券代码、交易日、开盘价、最高价、最低价、收盘价、成交量、数据来源、抓取时间、价格口径。建议补充成交额、换手率、流通市值和停牌状态。

用于对照：市场指数、行业指数及其日收益率、真实交易日历、交易时区、节假日和临时休市。若做个股收益预测，指数收益提供市场背景；若做事件研究，指数或行业收益用于估计正常收益。

质量要求：同一证券同一交易日唯一；OHLC 范围合法；成交量和单位一致；零成交量与缺失不是同一概念；不擅自插值停牌期间价格；明确涨跌停与可交易性。若跨市场，应分别处理时区、收盘时点和币种。

### 2.3 新闻、公告与事件

| 信息 | 建议字段 | 为什么需要 |
|---|---|---|
| 新闻原文 | 新闻 ID、标题、正文或授权摘要 | 支撑抽取、情绪和证据复核 |
| 来源与版权 | 来源机构、原始 URL、文档类型、许可说明 | 区分媒体报道、公司公告、转载与评论 |
| 多种时间 | 发布时间、更新时间、首次观察时间、入库时间 | 回测按当时可见版本和可用时间构造特征 |
| 关联主体 | 公司、证券、人物、行业、机构 | 支撑实体对齐及关系构建 |
| 事件 | 事件类型、主体、对象、数值、发生时间 | 支撑业绩、订单、政策、诉讼等不同事件的比较 |
| 提取证据 | 原文片段、字符位置、抽取模型与版本 | 能解释一条关系或标签来自哪里 |
| 可信与不确定 | 来源级别、转载关系、抽取置信度、人工核验状态 | 置信度是抽取可靠程度，不是事件真实概率 |

事件类型可先限定：业绩变化、订单与合同、研发进展、政策变化、并购重组、诉讼处罚、项目建设、管理层变动。应区分“已发生”“计划”“传闻”“被否认”。同一事件的多次报道需要事件 ID 与版本。

### 2.4 训练、评估和人工标注信息

- 预测标签：下一交易日收盘收益率；可另做涨跌分类，必须事先规定中性阈值。
- 情绪标签：正面、负面、中性，以及“针对哪个主体、影响哪个维度”；记录标注规范。
- 实体链接标签：文章里的公司提及实际对应哪只证券，以及拒绝链接的情况。
- 关系与事件标签：事件类型、主体、时间、原文证据，设置负例。
- 推荐人工核验 100—200 条新闻；数据较少时全量标注。按新闻类型与情绪分层抽样，多人重复标注一部分并报告一致性。实际数量取决于课程资源。
- 保存训练、验证、测试的日期清单、数据版本、代码版本、参数、随机种子和实验结果，防止只保留最好的一次。

### 2.5 数据来源选择

| 来源候选 | 适合获取 | 需要做的事 |
|---|---|---|
| 上海、深圳等交易所官网 | 交易日历、上市信息、公司披露索引 | 核查获取方式、访问限制和历史覆盖 |
| 巨潮资讯等公告平台 | 公司公告、业绩及重大事项 | 留原始公告链接，评估 PDF 文本提取质量 |
| Tushare 等有文档的数据服务 | 行情、交易日历、主数据等 | 核查账户权限、积分、字段口径、限额与许可 |
| AKShare 等开源接口工具 | 公开金融数据接口封装 | 按具体接口核验上游来源、稳定性、许可与日期覆盖 |
| 授权新闻 API、机构 RSS 或可用的公开新闻数据集 | 新闻内容与元数据 | 确认转载许可、精确时间戳、历史可用版本 |
| 自制合成数据 | 离线演示、异常输入与时序测试 | 显著标记为合成，不能用于真实市场效果结论 |

可查入口：[上交所](https://www.sse.com.cn/)、[深交所](https://www.szse.cn/)、[巨潮资讯](https://www.cninfo.com.cn/)、[Tushare](https://tushare.pro/)、[AKShare 文档](https://akshare.akfamily.xyz/)。这些是候选入口，不表示本项目已接通，或当前账户一定能免费获取所需字段。不要假设有一个接口能同时提供高质量历史新闻、精确可用时间和完整行情。

**数据决策表需要记录**：来源、字段、覆盖起止日、更新时间、精确度、费用、额度、许可证、接口失败方式和替代方案。若无法获取真实历史新闻可用时间，应降低研究主张，明确为回顾性关联分析，不能宣称完成了无前视偏差的可交易预测。

## 3. 需要完成哪些工作

### 3.1 数据收集与数据治理

需要实现：

- 统一采集接口：按证券、起止日期、来源获取原始记录；支持 CSV 离线导入。
- 原始层与规范层分离：保留原始响应、抓取时间和哈希；转换过程可追溯。
- 失败重试、限流、缓存、断点续抓；缺失要有状态，不能静默忽略失败记录。
- 行情去重、单位换算、日期和时区校验；新闻做 HTML 清理、编码修复与重复检测。
- 新闻按“规范化 URL＋标题/正文哈希＋时间邻近”识别转载；必要时聚类为同一事件，避免转载数量放大情绪。
- 区分文章更新版本，保留首次观察时间；没有真实观测时间的数据注明可用时间假设。
- 形成数据质量报告：缺失率、重复率、未知证券、覆盖交易日、异常价格、来源分布。

输出：原始数据目录、规范化数据表、数据字典、质量报告、来源说明。

### 3.2 实体抽取与实体融合

需要实现：

- 构建证券与公司主表及别名表，以唯一 ID 统一代码、简称和公司主体。
- 先采用词典匹配和规则，加入股票代码识别；记录重名、模糊提及和多公司新闻。
- 公司简称需要上下文消歧；品牌或子公司要经过明确关系映射。
- 若使用 LLM，要求输出结构化 JSON：实体、候选 ID、证据原文、置信度；用 JSON Schema 与已知代码清单校验。
- 无法确定时标记“待核验”，允许不建立关系；不得为了图谱完整度硬链接。
- 用人工标签评估实体识别与链接的准确率、召回率、F1，单独报告多义名称错误。

输出：实体表、别名表、新闻实体链接表、人工核验样本与链接质量指标。

### 3.3 时间融合与粒度统一

需要明确预测协议：**在交易日 t 的收盘信息已获得之后，预测下一交易日的收盘收益率**。

日频特征桶使用实际行情/交易日历中的收盘序列，将可用时间落在“上一次收盘之后、这一次收盘及之前”的新闻归入这一次收盘。盘后或周末新闻归到后续第一个有行情的收盘桶。跨市场及停牌证券采用相应日历，不能简单用自然日加一。

需要做：

- 统一到明确时区，保留原时区和时间精度；只有日期而无时分的新闻不能假装当天盘中可用。
- 可用时点使用真实采集记录、供应商可用记录或明确的保守假设，不能只依赖网站显示的发布时间。
- 新闻在 t 收盘后的更新不能覆盖回测中的 t 时点版本。
- 明确行情与新闻获取延迟。demo 假设精确 15:00 的新闻即时可用；真实系统应使用实际接收时间并设置决策缓冲。
- 定义新闻回看窗口、缺失标志和无新闻标志；不将“没有新闻”与“有中性新闻”完全混同。
- 对价格复权、样本证券名单、行业归属、财务数据发布日期执行同样的历史可用性检查。
- 若策略用下一日开盘成交，必须另做开盘收益、执行时点和滑点实验；不能将本 demo 的收盘到收盘目标直接解释为可实现交易收益。

输出：对齐后的“证券－交易日”融合表、未对齐新闻清单、时间对齐测试和时点假设说明。

### 3.4 知识图谱构建与存储

最小实体：公司、证券、行业、新闻、事件、来源机构。扩展实体：交易日、人物、政策、产品、财务指标。

| 关系 | 示例 | 属性与证据要求 |
|---|---|---|
| 公司－发行－证券 | 公司 A 发行证券 A | 主数据来源、生效区间 |
| 公司－属于－行业 | 公司 A 属于半导体 | 行业分类体系、有效期 |
| 来源－发布－新闻 | 来源 B 发布文章 N | 原始链接、发布/可用时间 |
| 新闻－提及－公司 | 文章 N 提及公司 A | 原文片段、匹配方法、置信度 |
| 新闻－报道－事件 | 文章 N 报道订单事件 E | 事件类型、主体、原文证据 |
| 事件－涉及－公司 | 事件 E 涉及公司 A | 人工或模型抽取依据 |
| 公司－关联－公司 | 母子公司、供应关系 | 仅在有可靠关系数据时加入；标注时效 |

需要做：

- 设计节点 ID、边唯一键、属性、来源与有效期；区分多个报道和同一个真实事件。
- 对抽取关系保留证据和模型版本；推断关系与原文事实分开保存。
- 小规模用 SQLite 存主表与关联表，属性图以 JSON 导出即可；图查询需求增多后再接 Neo4j。
- 提供查询：某证券关联哪些新闻/事件？某事件涉及哪些公司？一条关系原文来自哪里？
- 检查孤立节点、重复边、无证据关系、过期公司关系和未知证券。
- 谨慎使用“影响”边。新闻与价格同日波动只能形成“时间相关”观察，不能直接写成“导致上涨”。

输出：图谱 schema、图数据、查询接口、关系质量样本与可交互视图。

### 3.5 多维特征融合

| 层次 | 需要做的事 | 适用范围 |
|---|---|---|
| 数据层融合 | 股票/公司实体对齐、去重、时间归桶、统一单位 | 项目必须完成的基础 |
| 特征层融合 | 行情特征与新闻情绪、数量、事件、关系特征拼接 | 本项目主要预测实验 |
| 决策层融合 | 汇总不同模型估计与证据一致性，校准不确定性 | 后续可选，不以多数投票自动证明可靠 |

行情特征候选：1/3/5/20 日收益率、移动均线偏离、滚动波动率、成交量比、换手率、相对市场收益。新闻特征候选：数量、来源数、正负面比例、置信加权情绪、事件类别、事件强度、转载去重数量、时间衰减。图谱特征候选：关联主体数量、事件共现、可信供应关系上的邻居情绪；不需要一开始就上图神经网络。

需要做：仅使用历史窗口计算滚动特征；标准化、缺失填补、特征选择、词表拟合和模型训练都在训练集内完成；记录每个特征的定义、窗口、信息时点和缺失处理。LLM/大模型可能包含历史事件后验知识，应约束其只从提供的原文提取，不把自由生成的历史解释直接作为无偏回测特征。

输出：特征字典、融合特征表、特征可用时间检查、特征版本。

### 3.6 分析与可视化

必需：

- 股票选择、数据区间与来源标记、行情概览。
- 价格/收益走势叠加新闻落点，支持查看新闻原文信息和证据编号。
- 情绪与收益率、新闻数量与成交量的分布及滞后相关；标清样本量和滞后方向。
- 公司—新闻—事件—来源图谱，能够从图回到原始证据。
- 同期回测的模型指标、预测时点和真实标签展示；不只显示最新预测值。
- 缺失数据、尚未可用新闻、情绪模型局限等提示。

可选事件研究：预先定义事件样本、估计窗口和事件窗口，估计市场模型正常收益，计算 AR/CAR；剔除重复/重叠事件，讨论市场共同冲击，报告统计假设。事件窗口研究本身不能自动证明事件的因果效应。

输出：交互仪表盘、可导出的图表、分析摘要及证据列表。

### 3.7 行情预测与实验设计

最小预测目标：`y(t) = close(t+1) / close(t) - 1`。采用日收益率而非直接拟合价格，避免趋势曲线制造效果错觉。图谱首先服务证据组织；如果声称图谱改善预测，需要实际将图谱特征加入实验，而不是仅展示一个图。

必须比较：

1. 零收益/随机游走基线。
2. 历史均值或简单动量基线（正式实验补充）。
3. 纯行情线性/岭回归模型。
4. 行情＋新闻情绪/数量的融合模型。
5. 可选：再加入事件特征、图谱特征，分别做消融对比。

需要做：

- 按日期分训练、验证、最终测试；采用滚动或扩展窗口，禁止随机打散时间序列。
- 多股票实验按全局日期切分，避免同一天的数据同时进入训练与测试；处理跨股票共享新闻和跨日标签重叠。
- 超参数仅在训练/验证范围确定，测试集只用于最终评估；保留预测生成时点和训练标签截止日。
- 指标至少包括 MAE、RMSE、方向准确率、测试样本量；分类任务补充混淆矩阵与类别比例。
- 使用相同股票、日期、缺失处理和标签进行模型对比；避免样本范围变化造成假提升。
- 按股票、行业、行情阶段分别报告；研究统计稳定性时使用适合时序数据的区块重采样等方法。
- 记录融合失败的情况；若融合没有提升，也是有效课程结论，需要解释信息质量、噪声与样本规模。
- 如增加回测策略，另外定义开平仓规则、持仓、手续费、滑点、停牌及涨跌停处理，避免把预测误差直接解释为投资收益。

输出：固定实验协议、基线与融合模型、逐日预测日志、消融结果、误差分析。

### 3.8 智能体架构

建议采用“一个编排器＋受约束的专门角色＋共享数据/证据层”。不要求多个大模型彼此自由聊天。先实现确定性数据工具，再让 LLM 在工具边界内调度和解释。

| 角色 | 需要什么输入 | 需要完成的工作 | 输出 |
|---|---|---|---|
| 收集智能体 | 证券清单、日期、来源配置 | 采集/导入、校验、去重、记录来源与失败 | 数据快照、质量统计 |
| 融合/图谱智能体 | 主数据、新闻、行情 | 实体链接、时间对齐、事件抽取、图谱更新 | 融合表、图谱、证据 |
| 分析可视化智能体 | 融合数据、分析问题 | 调用统计分析和可视化工具，解释关联及限制 | 图表、统计结果、可核验观察 |
| 预测智能体 | 特征、标签、实验配置 | 按固定协议训练、回测、与基线比较 | 预测、指标、训练边界 |
| 报告智能体 | 结构化结果、证据 ID | 组织事实、模型结果、限制，验证引用 | 有引用的摘要 |
| 编排器 | 用户问题、任务状态 | 校验参数、分派任务、依赖管理、失败回退 | 一次完整运行记录 |

当前 demo 将融合和可视化数据准备合并到分析角色，共四个角色，编排器顺序执行。前端负责渲染图表。后续 LLM 扩展需要：

- 定义工具输入/输出 Schema、超时、失败状态和成本限制。
- 数据处理、指标计算和模型执行交给代码工具，大模型不自行编造数值。
- 报告中的数字回查结构化结果，引用回查证据 ID；缺证据时拒绝生成对应事实。
- 新闻文本作为外部数据，不作为系统指令；不允许新闻内容改变工具权限。
- API Key 从环境变量读取；记录调用模型、提示词版本、成本，不提交密钥。
- 输出严格区分观察事实、统计估计、解释假设和待核验事项。

输出：角色协议、编排流程、工具注册表、执行日志与证据校验器。

## 4. 技术选型与项目组织

| 模块 | 当前 demo | 正式课程项目可选扩展 |
|---|---|---|
| 数据层 | CSV、Python 标准库、SQLite | pandas、数据源适配器、Parquet |
| 抽取与情绪 | 输入字段＋规则词典 | 中文金融分类器、LLM 结构化抽取 |
| 图谱 | 内存属性图、JSON、SVG | Neo4j、Cypher、可查询子图 |
| 模型 | 标准库岭回归、扩展窗口 | scikit-learn、树模型；仅有足够数据时尝试深度模型 |
| 展示 | 本地 HTTP＋HTML/CSS/JS | FastAPI/Streamlit 等，按团队技术能力选择 |
| 编排 | 明确角色服务与顺序编排 | 工具调用代理、状态图、受约束规划 |
| 实验 | unittest、JSON 指标与日志 | 实验配置管理、数据版本与跟踪 |

优先把可复现的小闭环做好；Neo4j、向量库、复杂多智能体框架和图神经网络都不是项目成立的前提。技术组件只有在解决明确问题时才加入。
